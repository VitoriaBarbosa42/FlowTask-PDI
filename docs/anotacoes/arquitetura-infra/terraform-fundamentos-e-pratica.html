Terraform HCL, Redes Bridge no Docker & Manipulação de Arquivos no Linux

Guia didático consolidado da Fase 1 da Epic 5: os fundamentos de Infraestrutura como Código (IaC), ciclo de vida dos comandos Terraform, o papel dos Sockets e Redes Bridge, além de técnicas e armadilhas do terminal Linux/Bash.

Resumo Rápido em 3 Frases

O Terraform substitui scripts imperativos manuais por uma declaração arquitetural idempotente onde o arquivo de estado (terraform.tfstate) atua como fonte da verdade. Ele gerencia containers Docker falando diretamente com o daemon pelo Unix Socket (/var/run/docker.sock) e orquestra a comunicação entre serviços por meio de uma Rede Bridge customizada, que fornece DNS interno automático. No terminal Linux, comandos como touch, echo e cat aceleram a criação de arquivos, exigindo atenção com a expansão de histórico do Bash (!).

1. Por Que Isso Importa? (Contexto & Problema Real)

Em ambientes de desenvolvimento de microsserviços modernos (como o FlowTask, que reúne PostgreSQL, MongoDB, Redis, Kafka e Keycloak), existem três formas históricas de gerenciar a infraestrutura local:

1. Manual no Terminal

Rodar comandos soltos como docker run ... manualmente. Propenso a erros humanos, esquecimento de flags, IPs mutáveis e impossível de reproduzir exatamente na máquina de outro colega.

2. Docker Compose Puro

Melhora a repetibilidade através de um arquivo yaml, mas não possui gerenciamento de estado (statefile), não provisiona recursos de nuvem (AWS S3, SQS no LocalStack) com a mesma linguagem e tem modularização limitada.

3. Terraform (IaC)

Padrão da indústria: Código declarativo HCL, módulos reutilizáveis e isolados, planejamento com preview antes de aplicar (terraform plan) e paridade total entre ambiente local e nuvem real.

2. Explicação Conceitual & Modelos Mentais

A O Ciclo de Vida do Terraform e a "Fonte da Verdade" (State)

Diferente de scripts Bash comuns que executam comandos sequenciais sem memória, o Terraform opera por **Convergência de Estado**. Ele compara constantemente 3 entidades:

1. Código Desejado

O que você escreveu nos arquivos .tf (ex: quero uma rede bridge com nome flowtask-network).

2. terraform.tfstate

O registro em JSON com IDs, gateways e propriedades que o Terraform já provisionou no passado.

3. Mundo Real (Docker)

O que de fato existe ativo dentro do daemon do Docker na sua máquina.

Comandos Fundamentais na Prática:
  • terraform init: Inicializa o diretório de trabalho, baixa os providers declarados e gera o .terraform.lock.hcl.
  • terraform validate: Faz verificação estática de sintaxe e consistência de tipos sem criar nada.
  • terraform plan: Calcula o diferencial (delta) entre o código, o estado e o mundo real, gerando um preview do que será adicionado (+), alterado (~) ou destruído (-).
  • terraform apply: Aplica as mudanças no provedor (Docker/AWS) e atualiza atomicamente o terraform.tfstate.
  • terraform destroy: Destrói de forma limpa e na ordem inversa de dependências todos os recursos criados.

B O que é um Socket e por que usamos /var/run/docker.sock?

A palavra socket significa literalmente "tomada" ou "encaixe". Na computação, é o ponto final de um canal bidirecional de comunicação entre dois programas.

Socket de Rede (TCP/IP)

Comunicação via placa de rede (ou localhost) usando IP + Porta (ex: 127.0.0.1:5432). Usado por clientes web, navegadores e conexões externas. Possui overhead de empacotamento TCP/IP.

Unix Domain Socket (IPC)

Comunicação entre processos que vivem dentro do mesmo sistema operacional Linux. Representado como um arquivo especial (/var/run/docker.sock). Troca dados direto na memória RAM do kernel: é ultrarrápido e seguro por usar permissões de arquivo comuns do Linux.

C O que é uma Rede Bridge (Ponte) no Docker?

No mundo físico das redes, uma bridge (ponte) é um dispositivo que interliga dois segmentos de rede no nível de enlace (Camada 2 do Modelo OSI), comportando-se como um switch inteligente que encaminha pacotes com base nos endereços MAC.

No Docker, o driver bridge cria uma ponte de rede de software (switch virtual) dentro do kernel do Linux na sua máquina. Todos os containers conectados a essa bridge recebem seus próprios IPs virtuais em uma mesma sub-rede privada (ex: 172.23.0.0/16).

⚡ A Diferença Crucial: Default Bridge vs. User-Defined Bridge
Default Bridge (Padrão do Docker)
  • Todos os containers sem rede caem nela.
  • Não tem DNS embutido: um container não acha o outro pelo nome! Você é forçado a usar IPs fixos ou links legados.
  • Sem isolamento entre projetos diferentes.
User-Defined Bridge (Criada por nós no Terraform)
  • Nomeada como flowtask-network.
  • DNS Automático Ativo: o container do Keycloak conecta no Postgres usando simplesmente a URL postgres:5432!
  • Total isolamento contra outros containers da máquina.

4. Guia Hands-on: Comandos Linux para Criação e Manipulação de Arquivos

Durante o desenvolvimento de infraestrutura no terminal Linux (Ubuntu/WSL), frequentemente precisamos criar arquivos de configuração, diretórios e scripts. A seguir, os principais métodos compilados com seus prós e contras:

touch Criar arquivo vazio ou atualizar data de modificação Mais Comum

É o comando padrão para criar arquivos vazios instantaneamente. Se o arquivo já existir, ele não apaga nem modifica o conteúdo: apenas atualiza o carimbo de data e hora (timestamp) de acesso e modificação.

touch providers.tf variables.tf main.tf
echo Exibir mensagens e criar arquivos com texto Redirecionamento

O nome vem de "ecoar", pois ele imprime na tela (saída padrão / stdout) os textos ou variáveis de ambiente passadas. Quando combinado com operadores de redirecionamento, grava diretamente em arquivos:

1. Operador `>` (Sobrescreve ou cria o arquivo do zero): echo "valor_inicial" > config.txt
2. Operador `>>` (Adiciona texto ao final sem apagar o que já existe — Append): echo "nova_linha" >> config.txt
3. Flags Úteis do `echo`:
  • -n: Omite a quebra de linha final automática.
  • -e: Habilita a interpretação de caracteres especiais de escape (como \n para nova linha ou \t para tabulação).
nano Editor no Terminal

Abre um editor visual simples direto na janela do terminal. Cria o arquivo se ele não existir. Salva com Ctrl + O e sai com Ctrl + X.

nano terraform.tfvars
cat > arquivo Digitar antes de salvar

Permite digitar ou colar blocos de texto contínuos no terminal. Para finalizar a gravação e fechar o arquivo, basta apertar o atalho Ctrl + D (End of File).

cat > notas.txt

5. Armadilhas Comuns & Como Defender em Entrevistas

Armadilha 1: O erro -bash: !.gitignore: event not found Bash Interativo

O que aconteceu: No terminal interativo do Bash, o ponto de exclamação ! é reservado para History Expansion (ex: !ls repete o último comando de listagem). Quando colocado dentro de aspas duplas "...", o Bash tenta procurar um comando anterior chamado .gitignore no histórico!

❌ Incorreto: echo -e "*\n!.gitignore" > .docker/data/.gitignore
✅ Correto (aspas simples protegem caracteres especiais): printf "*\n!.gitignore\n" > .docker/data/.gitignore
✅ Ou em duas linhas: echo '*' > .gitignore && echo '!.gitignore' >> .gitignore
Armadilha 2: terraform init diz que teve sucesso, mas não baixou nada! Pegadinha HCL

Se o arquivo providers.tf for criado com tamanho 0 bytes (vazio / não salvo no VS Code), o Terraform roda e exibe "Terraform has been successfully initialized!", porém sem baixar nenhum provider!

Como diagnosticar:

Sempre observe se apareceram as linhas de download (Installing kreuzwerker/docker...) e verifique se o arquivo de trava .terraform.lock.hcl foi criado na pasta.

Dica de Ouro para Entrevistas de Estágio / Júnior

Quando te perguntarem: "Por que usar Terraform para subir Docker local em vez de apenas Docker Compose?", responda com segurança:

"O Terraform introduz idempotência e controle estrito de estado através do statefile, modularização HCL reutilizável e, principalmente, habilita o provisionamento dos recursos de nuvem simulados (AWS S3, SQS e Secrets Manager no LocalStack) usando exatamente os mesmos providers que utilizaremos na AWS real em produção, garantindo paridade total entre a máquina local e a nuvem corporativa."

6. TL;DR — Pontos-Chave para Revisão em 1 Minuto

  • IaC Declarativo: No Terraform, você declara o "o que deseja", e ele calcula os passos necessários para atingir o estado desejado.
  • Statefile é Sagrado: O terraform.tfstate guarda a correspondência entre código e o mundo real. Nunca deve ser editado manualmente.
  • Unix Socket: O Terraform fala com o Docker local via /var/run/docker.sock, dispensando rede TCP/IP e operando diretamente pela memória do kernel.
  • User-Defined Bridge: Redes bridge customizadas fornecem resolução DNS automática por nome de container, essencial para conectar Keycloak ao Postgres sem IPs manuais.
  • Terminal Linux: Use touch para arquivos vazios, echo '...' > arq com aspas simples para evitar problemas com !, e nano para edição rápida.
