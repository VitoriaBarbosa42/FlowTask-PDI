FlowTask — Plano de Estudos & Refinamento Técnico

Este documento consolida o refinamento sequencial de arquitetura, infraestrutura, mensageria e observabilidade do FlowTask. Desenvolvido para transformar o código em um case de engenharia de software de ponta, focado nos padrões adotados por grandes bancos de tecnologia como o Itaú.

Dashboard Visual & Kanban Interativo: Para gerenciar as histórias com drag & drop, marcar subtarefas e simular o fluxo de dados em tempo real, acesse o Hub Visual (index.html).

Parte 1 — Sprint Plan Sequencial

Cada sprint = 1 a 2 semanas. Ordem pensada para construir dependências sólidas.

Sprint 1-2 Epic 5

Infraestrutura como Código (Terraform)

Objetivo: Sair do docker-compose manual e provisionar toda a topologia local via Terraform.

  • Instalar Terraform + provider kreuzwerker/docker
  • Modularizar: modules/mongo, postgres, redis, kafka
  • terraform plan / apply substituindo o compose
  • (Stretch Goal) LocalStack para simular AWS S3 e SQS
Entregável Principal:

Repositório com pasta infra/ versionada e README explicando decisões.

Sprint 3-4 Epic 1

Persistência Poliglota Consciente

Objetivo: Justificar a arquitetura de cada banco por caso de uso, não por mero acúmulo.

  • Migrar dados transacionais do Kanban para PostgreSQL (JPA)
  • Manter PDI no MongoDB (documentos dinâmicos e sem schema rígido)
  • Redis como cache em memória do quadro Kanban (@Cacheable)
  • (Stretch Goal) Oracle XE local para tabela de auditoria/log corporativo
Entregável Principal:

ADR (Architecture Decision Record) explicando as motivações de cada banco.

Sprint 5-6 Epic 2

Mensageria & Comunicação Assíncrona

Objetivo: Kafka como espinha dorsal desacoplada entre Kanban e PDI.

  • Evento TarefaConcluidaEvent publicado ao concluir card
  • Consumer no módulo PDI reage e atualiza progresso no Mongo
  • Configuração de tópicos, partições e consumer groups (KRaft mode)
Entregável Principal:

Diagrama de fluxo de eventos + testes de producer e consumer.

Sprint 7 Epic 3

Microsserviço em Go

Objetivo: Praticar arquitetura poliglota real com serviço de alta performance.

  • Serviço em Go (Gin ou Echo) consumindo eventos do Kafka
  • Candidato: serviço de notificações ("tarefa concluída → dispara alerta")
  • Health-check expondo métricas básicas e consumo levíssimo de RAM
Entregável Principal:

Serviço standalone com Dockerfile multi-stage integrado ao Terraform.

Sprint 8 Epic 4

Observabilidade & Telemetria

Objetivo: Instrumentar a aplicação com métricas reais, além de simples logs.

  • Micrometer no Spring Boot (/actuator/prometheus)
  • Prometheus + Grafana local com painel de latência e contagem de eventos
  • Comparativo conceitual direto com a stack do Datadog utilizada no Itaú
Entregável Principal:

Dashboard Grafana com pelo menos 3 métricas de ouro do FlowTask.

Sprint 9-10 Epic 6

CI/CD + Testes + Fechamento

Objetivo: Pipeline de validação automatizada e consolidação de Clean Code.

  • Testcontainers para Postgres/Mongo/Kafka em testes de integração
  • GitHub Actions: lint → testes → build → terraform plan
  • Revisão geral de SOLID & Clean Code em commits semânticos
Entregável Principal:

Pipeline verde no CI/CD + README contando a jornada técnica para portfólio.

Parte 2 — Backlog de Refinamento por Épico

Histórias refinadas no padrão ágil, critérios de aceite interativos e argumentos para entrevista.

Epic 1 — Persistência Poliglota

Sprint 3-4
História 1.1 PostgreSQL (JPA)
"Como desenvolvedora, quero migrar o módulo de tarefas do Kanban para PostgreSQL, para ter dados transacionais com integridade relacional."
💡 Dica para Entrevista: Explique o teorema CAP e ACID: tarefas de kanban e colunas exigem integridade relacional estrita e chave estrangeira.
História 1.2 Redis Cache
"Como desenvolvedora, quero adicionar cache Redis nas consultas do board, para reduzir latência de leitura."
💡 Dica para Entrevista: Conhecer padrões de cache (Cache-Aside) e explicar como evitar o problema de dados obsoletos (stale data).
História 1.3 Stretch Goal
Oracle XE PL/SQL
"Como desenvolvedora, quero registrar auditoria de alterações em Oracle, para praticar a sintaxe PL/SQL."
💡 Dica para Entrevista: Grande diferencial para grandes bancos que possuem bases corporativas legadas e novas em Oracle.

Epic 2 — Mensageria e Comunicação Assíncrona

Sprint 5-6
História 2.1 Kafka Producer
"Como desenvolvedora, quero publicar um evento Kafka ao concluir uma tarefa, para desacoplar o Kanban do módulo PDI."
💡 Dica para Entrevista: Saber explicar o benefício de Publish/Subscribe: múltiplos serviços (PDI e Notifier Go) consomem o mesmo evento sem acoplar o Kanban.
História 2.2 Kafka Consumer
"Como desenvolvedora, quero consumir esse evento no módulo PDI, para atualizar o progresso automaticamente."
💡 Dica para Entrevista: Entender o conceito de Idempotência: como garantir que uma mensagem duplicada não compute pontos a mais no PDI.

Epic 3 — Microsserviço em Go

Sprint 7
História 3.1 & 3.2 Go / Gin / Docker
"Como desenvolvedora, quero criar um serviço de notificações em Go provisionado via Terraform, para praticar comunicação poliglota entre serviços."
💡 Dica para Entrevista: Destacar a eficiência de memória do Go (~15MB vs ~350MB JVM) e seu modelo de concorrência com goroutines.

Epic 4 — Observabilidade

Sprint 8
História 4.1 & 4.2 Prometheus / Grafana / Datadog
"Como desenvolvedora, quero expor métricas do Spring Boot via Micrometer e visualizá-las em um dashboard, para monitorar latência, throughput e saúde operacional."
💡 Dica para Entrevista: Conhecer os 3 pilares da observabilidade (Métricas, Logs e Traces) e explicar por que instrumentação supera logs puros em produção.

Epic 5 — Infraestrutura como Código

Sprint 1-2
História 5.1 & 5.2 Terraform / HCL / LocalStack
"Como desenvolvedora, quero provisionar Mongo, Postgres, Redis e Kafka via Terraform, para substituir scripts manuais por infraestrutura reproduzível."
💡 Dica para Entrevista: Demonstrar maturidade de DevOps: infraestrutura declarativa, versionada e idempotente, evitando drift manual.

Epic 6 — CI/CD, Testes & Fechamento

Sprint 9-10
História 6.1, 6.2 & 6.3 Testcontainers / Actions / SOLID
"Como desenvolvedora, quero testes reais com Testcontainers e pipeline de CI/CD completa com código revisado em SOLID, para garantir qualidade antes do deploy."
💡 Dica para Entrevista: O histórico de commits semânticos contando a história da refatoração é a prova cabal de evolução técnica em entrevistas.

Diretrizes de Execução & Dicas de Portfólio

1. Gestão no GitHub Projects: Vincule cada história de usuário ao seu Épico no quadro Kanban do repositório para manter rastreabilidade total.

2. Priorização Consciente: Priorize sempre o "Entregável Principal" antes de partir para os "Stretch Goals" — os stretches são bônus caso sobre tempo no ciclo.

3. Documentação como Portfólio: Ao concluir cada épico, registre 2 a 3 linhas no seu GitHub Pages de estudos conectando a teoria à implementação prática no FlowTask.
