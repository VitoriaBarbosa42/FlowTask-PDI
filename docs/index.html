1. Persistência Poliglota Consciente

Em entrevistas de System Design, usar múltiplos bancos sem justificativa é visto como overengineering. No FlowTask, cada banco atende a requisitos não-funcionais específicos:

  • Postgres: Integridade relacional (FKs, ACID, transações de colunas e cartões).
  • MongoDB: Schema flexível para o PDI (competências, metas dinâmicas, logs de feedback).
  • Redis: Cache de leitura sub-milissegundo para o quadro Kanban (`@Cacheable`).

2. Event-Driven & Desacoplamento

Quando um usuário conclui uma tarefa no Kanban, não queremos chamadas síncronas HTTP lentas ou falhas em cascata para atualizar o PDI ou disparar notificações.

  • Kafka KRaft: Alta taxa de transferência, retenção de eventos e replicação sem depender do ZooKeeper.
  • Consumer Groups: Múltiplos serviços (PDI e Notifier em Go) consomem o mesmo evento em ritmos independentes.

3. Observabilidade Corporativa

Diferença fundamental entre Logging e Observabilidade: não basta registrar erros, precisamos de métricas de golden signals (Latência, Tráfego, Erros e Saturação).

  • Micrometer: Facade padrão do Spring Boot para exportar contadores e timers.
  • Conexão Itaú/Datadog: Conceitos de tags, APM traces, percentis (p95, p99) e alertas.

ADRs (Architecture Decision Records) & Matriz de Decisões Técnicas

Use esta tabela como guia de estudo para justificar cada decisão arquitetural em conversas técnicas e defesas de código.

Decisão (ADR) Opção Escolhida Alternativas Rejeitadas Motivação Principal Trade-off / Desvantagem
ADR-001: Persistência do Kanban PostgreSQL (JPA) MongoDB puro / MySQL Garantia ACID, integridade referencial forte entre quadros, colunas e posições. Necessidade de migrations (Flyway) e schema rígido.
ADR-002: Estrutura do PDI MongoDB Document Tabelas normalizadas no Postgres Metas de carreira e competências possuem formato heterogêneo e evolutivo por usuário. Falta de joins nativos e validação de schema feita na aplicação.
ADR-003: Comunicação Inter-serviços Apache Kafka (KRaft) REST Síncrono / RabbitMQ Desacoplamento total, retenção persistente de eventos de conclusão e suporte a múltiplos consumidores. Maior complexidade de setup local e consistência eventual.
ADR-004: Serviço de Notificações Go (Gin Framework) Outro módulo no Spring Boot Praticar arquitetura poliglota real, consumo de memória ínfimo (~15MB vs ~350MB JVM) e inicialização instantânea. Necessidade de manter dois pipelines de build e runtimes distintos.
ADR-005: Provisionamento de Infra Terraform (Docker Prov.) docker-compose estático Modularização declarativa (`modules/mongo`, `modules/postgres`), aproximação com padrão de produção cloud (AWS). Curva de sintaxe HCL e gestão de state (`terraform.tfstate`).
ADR-006: Estratégia de Testes Testcontainers (JUnit 5) H2 Database em memória Testar contra os motores reais do Postgres, Mongo e Kafka, eliminando falsos positivos do H2. Tempo de execução de testes ligeiramente maior devido ao startup de containers.
